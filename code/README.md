# NanjingTrip Agent — 南京市内行程规划 AI Agent（本地 Web 版）

> 《软件设计II》课程设计作品 · 南京邮电大学 ＿＿＿
> 单人独立完成 ｜ 设计周期 2026-10-27 ～ 2026-11-03

## 1. 它做什么

用户在界面用**一句自然语言**告之说"某天在某地做某事、大概耗时多久"，系统自动完成：

1. **意图解析**：自然语言 → 结构化任务（日期 / 期望时段 / 地点表述 / 事项 / 耗时 / 类别）；
2. **地点消歧**：地点表述 → 南京市内唯一 POI（名称、地址、行政区、经纬度），并把非南京地点挡在门外；
3. **通行估算**：相邻待办之间自动查询通行时长（驾车 / 公交 / 步行），结果本地缓存复用；
4. **行程编排**：在"已有安排 + 各项耗时 + 通行时长 + 缓冲时间"约束下求出无冲突时间轴，冲突时给出可执行建议；
5. **本地持久化**：行程、事项、地点、通行段、版本全部存本地 SQLite，关掉重开数据仍在，可回滚历史版本；
6. **界面呈现**：日历（有行程的日期标蓝加粗）+ 当日时间轴（含通勤段）+ 当日统计（事项/通行/空档）；
7. **多方式对比与逐段选择**：每条通勤段并排显示 驾车/公交/步行 三种时长，点哪个就按哪个重排，
   且**只改这一段**；也可在解析结果卡里指定本段方式（说"坐地铁去…"也会被识别）；
8. **出行建议**：给出"最晚几点出发"（按真实通行时长 + 缓冲倒推）与"躲高峰备选"，
   并标明时段系数为本地经验值而非高德预测；
9. **公交换乘方案**：线路、上下车站、站数、步行距离、票价、首末班时间；班次按经验发车间隔
   推算并明确标注"非实时到站"；
10. **位置示意**：当天地点按时间顺序在静态地图上以序号连线（底图取自高德，连线与序号本地绘制）；
11. **冲突一键采纳**：冲突对话框里每条建议都有「采纳」按钮（顺延 / 缩短 / 换方式 / 移到次日 / 取消）；
12. **AI 助手**：除行程问答外可作通用问答，主线程取数、工作线程请求，避免界面卡死。

**离线降级**：没有配置任何 API Key 时自动进入离线模式（内置 53 条南京 POI + 距离估算通行时长 + 规则解析），
答辩现场断网也能完整演示；配置 Key 后一键切到在线（DeepSeek 等 OpenAI 兼容大模型 + 高德地图 Web 服务）。

## 2. 运行方式

```bash
# 1) 依赖
pip install -r requirements.txt

# 2) 启动（首次运行会在 %LOCALAPPDATA%\NanjingTrip 建库）
#    浏览器会自动打开 http://127.0.0.1:8765
python main.py

# 3) 常用参数
python main.py --demo                      # 启动并写入演示数据（答辩推荐）
python main.py --date 2026-10-28           # 定位到指定日期
python main.py --data-dir D:\tmp\ntrip     # 指定数据目录（隔离演示/测试）
python main.py --city 北京 --demo           # 切换城市并填充演示数据
python main.py --no-browser                # 只起服务（脚本/演示用）
python main.py --port 8800 --host 127.0.0.1   # 换端口、只监听本机
```

## 3. 配置 API Key（可选）

界面「设置」中填写，或直接编辑 `%LOCALAPPDATA%\NanjingTrip\secrets.json`：

| 项 | 说明 | 默认 |
|---|---|---|
| 大模型 | OpenAI 兼容接口（DeepSeek / 通义千问 / 智谱），温度 0，强制 JSON | `deepseek-flash` @ `https://api.deepseek.com/v1` |
| 思考开关 | `llm_reasoning_effort`：推理型模型（如 `deepseek-flash`）解析时**关闭思考**（结构化抽取不需要，实测单次 2908→1760 ms） | `none`（留空则不下发该参数） |
| 地图 | 高德地图 Web 服务 Key（POI 检索 + 路径规划） | 离线内置 POI |
| 交通方式 | driving / transit / walking | driving |
| 逐段择优规则 | 「每段自动选最快」开启时：≤500 m 直接步行；≤1500 m 不参与驾车比较；**骑行 >30 分钟、步行 >45 分钟不参与择优**（体力阈值，仍可手动「换方式」） | 见 `TripService.pick_fastest_mode` |
| 缓冲 | 每段通行后额外保留的候车/找车位时间 | 10 分钟 |
| 可排时段 | 自动择时允许的区间 | 08:00–22:00 |

> 密钥存 `secrets.json`（仅当前用户可读），**不写入数据库、不打印日志**；`config.json` 只存非敏感配置。

### 两路独立降级（四种运行状态）

大模型与地图**各自判断可用性**，不会因为缺一个 Key 就把另一个也关掉：

| 状态 | 条件 | 表现 |
|---|---|---|
| 在线 | 两个 Key 都有且未强制离线 | 真实大模型解析 + 真实高德通行时长 |
| 半在线（只有地图 Key） | 地图可用、大模型不可用 | **真实 POI 与通行时长** + 规则解析兜底（答辩最省事的组合） |
| 半在线（只有大模型 Key） | 大模型可用、地图不可用 | 真实大模型解析 + 内置 POI 与距离估算 |
| 离线 | 无 Key 或强制离线 | 内置 53 条南京 POI + 规则解析，断网可完整演示 |

状态栏显示 `● 在线 / ● 半在线 / ● 离线` 及具体装配情况；工具栏「离线模式」按钮随时可强制切换。
界面底部状态栏与 `设置` 对话框都会如实标注当前两路各自用的是真实服务还是离线兜底。

## 5. 测试

测试分两层，职责不同：

```bash
cd code
python -m pytest tests -q              # 第一层：离线回归，231 passed（约 35 秒）
python -m pytest -m online -q          # 第二层：联网验收，9 passed（约 60 秒）
```

* **第一层 · 离线回归**（默认跑）：内置城市包 + 规则解析 + 距离估算，不碰外网，
  保证结果可重复、不烧配额、断网也能跑。改动任何逻辑先跑这一层。
* **第二层 · 联网验收**（`-m online` 显式跑）：接真实 DeepSeek 与高德，跑用户真实会走的那条链路
  ——真实模型 JSON 契约、批量解析真实案例、四方式对比与路径折线、统计口径一致性、AI 问答。
  断言只写**结构 / 区间 / 一致性**，不写死具体时刻（路况与措辞都会变）。
  按"验收环境一定有网络"的前提设计，**不设 skip**：缺 Key 或断网直接失败，不把"没测"伪装成"通过"。

测试覆盖：解析（日期/时刻/耗时/地点/交通方式/缺字段）、排程（空集/单任务/通行插入/期望时段/锁定/无空档/重叠/缓冲/超时段/可解释说明）、
仓储（读写一致/缓存唯一键/版本上限/老库 mode 列迁移）、配置（密钥分离/缺 Key 自动离线）、集成（离线全链路/缓存命中/冲突与建议采纳/调整/删除/回滚/统计）、
出行建议与公交方案（班次推算、非实时标注）、路径详情（骑行/步行接驳不被"更快者"替换）、逐段独立出行方式、批量删除与撤销、
局域网多端同步（真实 HTTP 服务 + 两端交替写）、位置示意图（地图投影纯逻辑）、助手问答（跨线程读库回归）、
统计口径一致性（统计条与排程说明同一个数）、离线标题形态。

## 开发与自测

- **改前端**（`web/app.js`、`app.css`、`index.html`）**不需要重启**：静态文件每次请求现读，
  刷新页面（Ctrl+F5）即可。
- **改后端 `.py`**：用 `python tools/dev.py --port 8765` 起服务。它**不弹浏览器**，
  检测到 `.py` 变更会自动重启，端口保持不变。
- 界面是单页应用：切换日期/页面用 `history.replaceState` 更新地址栏，不做整页重载。
- 案例测试留档在仓库外的 `07_测试留档/`（`案例一_报告.md`、`案例二_报告.md` 与逐步截图）。
