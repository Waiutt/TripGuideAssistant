> 被测对象：`code/nanjingtrip/consult.py`（多轮行程顾问的意图与槽位层）
> 用例：`code/tests/test_intent_modify.py`（50 条，M-01~M-50）、`code/tests/test_intent_prune.py`（50 条，P-01~P-50）
> 运行：`cd code; $env:PYTHONIOENCODING="utf-8"; python -m pytest tests/test_intent_modify.py tests/test_intent_prune.py -q`
> 结果：**63 通过 / 37 xfail / 0 失败 / 0 xpass**；全量 `python -m pytest tests -q` = 767 passed, 194 xfailed, 7 xpassed, **0 failed**

## 0. 一句话结论

修改类的失败集中在**"数字与时刻的基础归一"（中文数字、上/下午）**和**"同义词没进词表"**，删除类的失败集中在**"整天删除没有通道"和"删不存在的东西时全程静默"**——软排除与逐项硬删除这两条主干都是对的，数据契约守住了，缺口在口语的边角上。

## 1. 测试口径（为什么这么判）

**先在前面建一份行程，再改/删。** 只有草案的会话谈不上"改"，所以每条用例先发一句底稿：

* 修改类底稿 `BASE`＝`11月14号到16号去南京玩，想去南京博物院、总统府和夫子庙，每天两个点`，之后才发待测句（与 `test_intent_matrix.py` 的 `NEEDS_BASE` 同一做法）。
* 删除类底稿同上，**并且真的写库**（`ctx.trip_svc.add_batch(2026-11-14, [南京博物院/总统府/夫子庙])`）。只跑 `chat()` 拿到的是草案、不写库，那样永远测不到"删掉了没有"。

**两条删除契约必须分开判：**

| 说法 | 落点 | 判据 |
| --- | --- | --- |
| 软排除：别去 X / 不想去 X / X 我不想去了 / X 别去了 | `slots.avoid` | 槽位写入 **且** `day_view(day).tasks` 条数**不变** **且** 回复里没有"删掉" **且** 新草案里不再出现 X |
| 硬删除：把 X 去掉/删掉/拿掉、X 不要了 | 真删数据 | 当天事项**少 1 条**、X 从 `tasks` 里消失、回复**点名**"已…删掉：2026-11-14 X" |
| 删除整天：这天清空 / 整天删掉 | —— | 当天 `tasks` 清空 |
| 删除不存在的项 | —— | 数据不动 **且** 回复要点名"行程里没有它" |

**关于硬删除的槽位断言（重要设计事实）：** `slots.drop` 是"待执行指令"，`Consultant.chat()` 在 `_apply_drops()` 里执行后立刻把它清空，所以**返回的 `slots.drop` 永远是 `[]`**。因此硬删除**不能**用 `slots.drop` 判定，只能看服务端数据 + 回复文案；用例就是这么写的（实测每条硬删除用例的 `drop` 都是 `[]`，而数据确实少了一条）。

## 5. 疑似缺陷段（复现句子 / 期望 / 实际 / 最小修复建议）

> 建议只写在报告里，本次**未改任何代码**。

### F-01 中文数字不归一（组 A，7 条）
* 复现：`改成五天` / `变成两天` / `每天别超过两个点` / `我十点起床` / `晚上十一点以后回酒店`
* 期望：`trip_days=5`、`trip_days=2`、`per_day=2`、`wake=10:00`、`day_end=23:00`
* 实际：`trip_days=0`（草案仍 3 天）、`per_day=0`（草案每天仍 3 点）、`wake=09:00`、`day_end=''`
* 最小修复：加一个 `zh_num(text)`（一~十五 + 两/廿/半）把中文数字折成阿拉伯数字，**只在解析入口折一次**，四处正则原样复用。注意"两点"（时间）与"两点"（个数）的歧义：只折紧跟 `天|个|点+|点半|月|号` 的片段，并优先按"数量"解释，时间场景保留原文匹配。

### F-02 同义词没进词表（组 B，7 条）
* 复现：`别太赶`（pace 不动）、`预算不多` / `预算有限`（budget 为空）、`午饭在德基广场解决`（meal 为空）、`别安排夫子庙` / `不要安排总统府`（avoid 为空）、`夫子庙删了吧`（整句没识别）
* 期望：`pace=slow`（或 `per_day` 下调）、`budget=省`、`meal=德基广场`、`avoid=['夫子庙']`、真删 1 条
* 实际：`pace=normal`、`budget=''`、`meal=''`、`avoid=[]`、事项 3→3
* 最小修复：把词表从"枚举短句"改成"动词词根 + 语气词剥离"：节奏词加 `赶|紧|慢|松|累|体力`，预算加 `预算(不|有限|紧)|手头紧`，吃饭动词表加 `解决|搞定|安排`，排除动词表加 `别安排|不要安排|删了吧|拿了吧`（`删了` 与 `删掉` 同义）。

### F-03 上/下午不归一（组 C，1 条）
* 复现：`晚上10点回酒店`
* 期望：`day_end=22:00`
* 实际：`day_end=10:00`（`min(23, hh+1)` 只对 hh≥23 起作用，10 点原样落库）
* 最小修复：解析前先判时段词（`晚上|夜|晚` → 12 小时制 +12，`凌晨` → 保持，`中午` → 12），再做 `hh` 上限裁剪；`23 点后` 的 `+1` 逻辑保留。

### F-04 "不用酒店 / 当天往返"没有落点（组 D，2 条）
* 复现：`不用酒店`、`不需要酒店`
* 期望：`hotel` 有一个明确值（例如 `none`），后续不再追问住宿、方案里不出现酒店锚点
* 实际：`hotel=''` —— 与"还没问过住宿"完全同值，`questions()` 每轮都会再问一次
* 最小修复：`_PICK_HOTEL` 同级加一组否定词表 → `hotel='none'`；`questions()` 里 `hotel in ('', ...)` 的判断把 `'none'` 排除；`build_plan`/`_build_practical` 里 `'none'` 视为"当天往返、不挂酒店"。属产品决策，见 §6。

### F-05 顾问层没有"段落交通方式"（组 D，2 条）
* 复现：`这段改步行`、`这段改骑车`
* 期望：至少有一个可观察结果（槽位或草案里的段落方式）
* 实际：`ConsultSession.FIELDS` 无 `mode`，`absorb()` 无对应分支，槽位与草案**一模一样**
* 最小修复：**不是**在顾问里塞 mode（那会与 `AssistantService.route` 的 per-task 方式打架）。更小的修法是在 `absorb()` 里识别到"改步行/改骑车/全部步行"时，回一句明确的引导（"这一段的方式在当天时间轴里改，或说「第 2 段改骑车」"），并把它记到 `note`。是否要在顾问层支持，见 §6。

### F-06 "再来一版"没有可观察结果（组 E，1 条）
* 复现：`再来一版`
* 期望：新版与上一版可区分（变体维度/序号/说明）
* 实际：草案、`slots`、`message` 与上一轮逐字相同
* 最小修复：确定性规划下"再来一版"必然同结果，所以要么给 `build_plan` 一个 `variant` 参数（换主题/换区域/换节奏三种候选，`TripService.alternatives` 已有同构能力），要么在回复里明确说"约束没变，重排结果一样；想换可以点这几类"。属产品决策，见 §6。

### F-07 窗口会话里加天被旧跨度夹住（组 F，1 条）
* 复现：`11月中旬去南京玩` → `多加一天`
* 期望：`days_total` 3→4（窗口 11-11~11-20 有 10 天可用）
* 实际：`days_total` 3→3；`trip_days` 被写成 3
* 根因链：第一轮 `build_plan()` 末尾 `st.start = days[0]['date']; st.end = days[-1]['date']` 把窗口收敛成 3 天 → 第二轮 `date_span=3` → `min(base+1, max(1, date_span))` 夹回 3
* 最小修复：`st.window` 为真时，加/减天的上限改用 `win_start~win_end` 的天数，而不是 `date_span`；或者不要在 `build_plan` 里改写 `st.start/end`（另存 `plan_start/plan_end`）。

### F-08 "你帮我选"同时命中住宿与餐饮（观察到的副作用，未单独立案）
* 复现：`午饭你帮我选`（M-37）
* 期望：只写 `meal=recommend`
* 实际：`meal=recommend` **且** `hotel=recommend`（`absorb()` 的 `_PICK_HOTEL` 只看字面"你帮我选"，不看后面跟的是住宿还是吃饭）
* 最小修复：`_PICK_HOTEL` 命中后再校验句子里是否有住宿词（`住|酒店|宾馆|民宿`），没有就不写 `hotel`。

### F-09 "再加一天"顺手放宽每日点数（观察到的副作用，未单独立案）
* 复现：`再加一天`（M-02）
* 期望：只加 1 天，`per_day` 不变（3）
* 实际：`days_total=4` 正确，**但 `per_day` 3→4**（微调分支的 `'再加'` 命中"多点"）
* 最小修复：`'再加'` 只在后面不是"天/日期/小时"时才放宽点数；或把加天分支移到微调分支之后并 `return`。

### F-10 点名餐厅被当成"必去景点"（观察到的副作用，未单独立案）
* 复现：`中午去南京大牌档德基店吃饭`（M-40）
* 期望：只写 `meal`
* 实际：`meal=南京大牌档德基店` 正确，**同时 `must` 里多了这条**（"想去/去吃"的并列抓取未排除餐饮类）
* 最小修复：`must` 追加前先 `poi.kind == '餐饮'` 时跳过（`_place_in_chunk` 那条已经在过滤 `交通/住宿`，补上 `餐饮`）。

### F-11 "换掉"被当成硬删除（组 G，2 条）
* 复现：`夫子庙换掉`、`把总统府换掉`
* 期望（按本次口径：换掉属软排除）：`avoid=['夫子庙']`，事项 3→**3**
* 实际：`avoid=['夫子庙']`，事项 3→**2**，回复含"删掉"
* 最小修复：`_HARD_NO` 里去掉 `换掉`（保留在 `_SOFT_NO`），或在 product 层确认"换掉 = 删掉并重排"后把用例口径改成硬删除。属产品决策，见 §6。

### F-12 没有"清空整天 / 按天删除"的通道（组 H，5 条）
* 复现：`这天清空吧`、`这一天的安排全删掉`、`把第二天清空`、`整天删掉`、`这天去掉`
* 期望：当天 3 项清空
* 实际：`avoid=[]`、`drop=[]`，事项 3→3（一个字都没动）
* 根因：`exclusion_names()` 的四个正则都要"地名 + 动词"，"这天/整天/第二天"经 `_trim_to_place()` 裁不出地名就整条丢弃
* 最小修复：在 `exclusion_names()` 之前加一条独立分支：命中 `(这天|当天|整天|这一?天|第[一二三四五六七八九十\d]天)\s*(清空|删掉|去掉|取消|全删)` → 记 `st.clear_day = 目标日序号`（当天=0/序号 n），由 `chat()` 调 `TripService.delete_many()` 清空；窗口/多日会话按 `_span_days()` 定位。

### F-13 "今天/这天"覆写整趟行程日期（组 I，2 条）
* 复现：`把今天的夫子庙去掉`、`今天的不去了`
* 期望：删除作用在**已排的 11-14**（或至少不改整趟日期）
* 实际：`start` 被改成 `2026-11-01`、`days_total` 变 1，事项 3→3（删除打在空日期上）
* 最小修复：`absorb()` 里"只说相对日（今天/明天/后天）且会话已有区间"时，把它记成 `st.target_day`（用于删除/定位），**不要**改写 `st.start/st.end`。

### F-14 删不存在的项全程静默（组 J，7 条）
* 复现：`把人民大会堂去掉`、`把西湖去掉`、`把外滩去掉`、`把中山陵去掉`、`把故宫删掉`
* 期望：数据不动（已满足）**且**回复点名"行程里没有 人民大会堂 / 已确认没排进来"
* 实际：事项 3→3，回复里一个字都不提；`把故宫删掉` 还把 `avoid` 写成了 `明故宫(地铁站)`
* 最小修复：`_apply_drops()` 返回 `removed` 之外再返回 `not_found`（在 `_span_days` 内既没匹配到 tasks、`_resolve_place` 也解析不出），`chat()` 把"没有 X 这一项，可能还没排进来"拼进 `msg`；同时 `_trim_to_place()` 的包含匹配加上长度差阈值（现有的 `nm_key_ok` 已够用，`_resolve_place` 的"前缀/包含"分支绕过了它）。

## 6. PENDING-DECISION（需要产品口径，不能由测试单方面定）

1. **"X 换掉"是软排除还是硬删除？**（P-15/P-16）当前实现按硬删除（真删数据 + 回复"删掉"），本次用例按"软排除"口径判为不通过。若确认"换掉=删掉重排"，只需改用例口径，不必改代码。
2. **"不用酒店 / 当天往返"用什么值表示？**（M-35/M-36）`hotel=''` 现在同时表示"没问过"和"不用"，追问会无限循环。建议新增 `hotel='none'`，但要定：不挂酒店锚点后，第一天的"从哪出发/回哪"用起点还是留空。
3. **"这段改步行/骑车"归哪一层？**（M-42/M-43）能力已存在于 `AssistantService.route`（逐段 per-task 方式），顾问会话里是否也要支持？若不支持，至少要回一句"在这儿改不了，去时间轴里改"。
4. **"再来一版"要不要确定性变体？**（M-44）同约束必然同结果，是否引入"换主题/换区域/换节奏"三种变体维度（`alternatives()` 有同构能力）。
5. **"再加一天"顺带放宽每日点数**（F-09）与 **"你帮我选"顺带选住宿**（F-08）是 bug 还是特性，需确认后再决定修不修。
6. **"删除整天"要支持到什么粒度？**（P-33~P-37）"这天/整天"是否指"当天"，"第二天"是否按序号定位；以及"今天"这类相对日期要不要覆写整趟行程（P-38/P-45）。
