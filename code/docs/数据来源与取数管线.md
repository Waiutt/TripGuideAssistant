# 数据来源与取数管线（营业时间 / 票价 / 评分 / 推荐游玩时长）

> 原则：**规划时用真数据，不靠写死，也不靠我拍脑袋。**
> 城市包（`cities.py`）里的 `open_from/open_to/visit` 只是**演示种子**，
> 在线时会被真实取数覆盖；取不到才回落到种子值，并在界面上说明。

## 一、取什么、从哪取

| 数据 | 来源 | 是否实时 | 落地位置 | 说明 |
|---|---|---|---|---|
| 坐标 / 地址 / 行政区 | 高德 `place/text` | 实时 | `poi` 表 | 解析地点时的主数据 |
| **营业时间** | 高德 `place/text?extensions=all` 的 `biz_ext.open_time` | 实时 | `poi_intel` 表（缓存） | 形如 `09:00-17:00`、`24小时营业`、多时段；取首个时段 |
| **闭馆日** | 同上（`…;周一闭馆`） | 实时 | `poi_intel.closed_days` | 解析为 `一`/`二`… |
| **票价** | `biz_ext.cost` | 实时 | `poi_intel.cost` | 免费为 `0`，为空表示未标注 |
| **评分** | `biz_ext.rating` | 实时 | `poi_intel.rating` | 用于时长估算与排序 |
| **推荐游玩时长** | ⚠ 无公开 API | — | `poi_intel.visit_min` | 见下节：按类型+评分+营业窗口**估算**，标注 `estimate` |
| 通行时长 / 距离 | 高德 `direction/*` | 实时 | `transit_leg` 表（缓存） | 驾车/步行/公交/骑行分别取数 |
| 天气 | 高德 `weather/weatherInfo` | 实时（今天+3 天） | 内存缓存 | 窗口外一律 `null`，不猜 |

## 二、推荐游玩时长为什么是"估算"而不是"抓来的"

- 高德 Web 服务**不提供**"建议游玩时长"字段（`biz_ext` 只有 `open_time/cost/rating`）；
- 携程 / 马蜂窝 / 百度百科等页面虽然有类似表述，但**没有开放 API**，抓取属于爬虫，
  既不稳定也不合规，本项目不采用；
- 因此采用**可解释的估算**：`类型基线 × 评分加成，且不超过营业窗口的 80%`，
  并把来源标注为 `estimate`，界面上写明"按类型与营业时间估算，可改"。

估算规则（`nanjingtrip/intel.py::estimate_visit_min`）：

| 高德类型关键字 | 基线 |
|---|---|
| 博物馆 / 纪念馆 / 展览馆 / 科技馆 | 120 分钟 |
| 动物园 | 150 分钟 |
| 国家级景点 | 120 分钟 |
| 风景名胜 / 公园 | 90 分钟 |
| 寺庙 / 道观 | 60 分钟 |
| 商业街 / 书店 | 60 分钟；购物中心 90 分钟 |

调整：评分 ≥ 4.7 加 20%；有营业窗口时上限为窗口时长 × 80%（下限 45 分钟）；
结果取整到 10 分钟且不突破上限；没有地点信息时才退回 60 分钟。

## 四、缓存与失效

- `poi_intel` 表按 `(city, name)` 主键缓存，取过一次就不再联网；
- 需要刷新时删掉对应行（或整表）即可，下次规划自动重新取数；
- 用户手动改过时长后，以用户值为准（预览卡里改的 `duration_min` 会随任务写库）。

## 五、与城市包的关系

城市包的 `visit/open_from/open_to` 只在**离线**或**取数失败**时生效，作用是：
让整套演示在没有网络、没有 Key 的机器上也能跑；一旦联网，真实数据优先。
`code/tests/test_intel.py` 用伪造的高德响应守死"解析 → 缓存 → 覆盖种子"三条链路。

## 六、推荐游玩时长的证据层（P1 已实现，不含用户回填）

`visit_evidence(city, name, source, minutes, note, checked_at)` 三级来源：

| 来源 | 谁填 | 优先级 | 区间浮动 |
|---|---|---|---|
| `official` 官方口径 | 人工核对官网/公众号/博物馆推荐路线，用 `tools/import_visit_evidence.py` 导入 | 最高 | ±10% |
| `ota` 平台登记 | 同上（多平台登记值） | 中 | ±20% |
| `estimate` 估算 | 系统现算（类型 × 评分 × 营业窗口） | 兜底 | ±35% |

取值规则：official > ota > estimate；对外给**区间**（如「1 小时 50 分–2 小时 10 分 · 官方口径」），
排程用区间中值；预览卡上会显示「时长（来源 区间）」，用户仍可手改。
**按要求不做"用户回填实际用时"的闭环**。
