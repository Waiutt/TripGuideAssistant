# 演示脚本（明天现场，8 分钟主线 + 备用场景）

> 原则：**只演已经真实跑通的东西**；每一段都准备一句"如果这里出问题"的兜底话术。
> 主入口是**起始页**（顾问台），不是工作区。

## 一、开场（30 秒）

> "这是南京市内的行程规划 Agent。它做三件事：**听懂人话**、**用真实数据**、**把行程算出来**。
> 理解交给大模型，算术和约束全部交给代码——所以我们不会编景点时长、不会把地名认错还硬排。"

## 二、主线：一句话 → 三天行程（约 3 分钟）

**输入（照抄，别临场改）**：

```
我想11月份中旬找空挡在南京市区旅游，但是我很懒。一般10点起床，晚上可以23点后到酒店，
你给我规划一下大家比较推荐的景点然后规划一下，但是呢，其中有一天我要去栖霞区南京邮电大学
找朋友中午吃饭聚餐，你给我规划后我来约朋友，他工作日没空，你得给我推荐一下什么时候去
```

**讲解点（边等边说，这一轮约 3–4 秒）**：

1. 它没有把 10 天窗口排满 → 先给 **3 天**（"想多玩几天说一句就行"）；
2. 「他工作日没空」被当成约束 → **朋友那天落在周六**，并直接告诉你约哪天；
3. 住宿没有擅自决定 → **追问 + 3 家候选**；正餐也没替你挑店 → 问"就近随便 / 你帮我选 / 口味"。

**接着回答两个追问**：点一家酒店 → 点「就近随便」→ 草案刷新。

**讲解点**：起点 10:00（听"很懒"）、每顿留 60 分钟、跨区通行按真实驾车时长。

## 三、写入与时间轴（约 1.5 分钟）

点「查看并写入」→ 面板里确认 → 写入后看当天时间轴：

- 起点 10:00、通行段、午饭、回酒店余量；
- 「该日已有 N 项 → 本次是追加」的提示（如果当天原本有安排）。

**讲解点**：写入是**追加不是覆盖**，同名地点不会排两遍；每天一份行程，日历可逐天看。

## 四、即时修改（约 1.5 分钟）

在起始页继续说（这两句都能真跑）：

| 说 | 预期 |
|---|---|
| `我不想去老门东` | 草案里不再出现老门东；**已写进行程的那条不动**（软排除） |
| `11月14号这天把中山陵去掉` | 真的从行程里删掉，并回你"已按你说的从行程里删掉：2026-11-14 中山陵"（硬删除） |
| `11月14号那天再加个总统府` | 总统府进草案（点名必去不被排名挤掉） |

**讲解点**：区分"别排进来"和"从行程里拿掉"——这是两类不同操作，系统分得清。

## 五、断网演练（约 1 分钟，最能打）

点左栏「强制离线」→ 把上面第一句话再说一遍 → **同样出方案**。

**讲解点**：城市包 906 个点位在本地；没有网也能规划、能解释，只是时长标注为估算。这是"异常与降级"要求。

## 六、收尾（30 秒）

打开体检/测试数字（或在报告里指）：

> "代码有 436 条离线用例 + 89 条扩展用例全绿，还有一个 20 秒跑完的体检脚本；
> 缺陷记录到 D-90，每一条都有根因和回归用例。"

## 七、备用场景（现场被要求时再演）

| 场景 | 一句话输入 |
|---|---|
| 吃的地点我说了算 | `明天中午在德基广场吃饭，下午去南京博物院看展2小时` |
| 地名堆录入 | `总统府 夫子庙 老门东 鸡鸣寺`（走批量录入卡，不是提案） |
| 认不出的地名 | `明天下午去辰龙广场`（应标"待补地点"，不臆造） |
| 太满要取舍 | 写入 8 项后问 `这天太赶了怎么办`（给取舍建议） |
| 数据规模 | 左栏「更多」里看库规模/维护（或跑 `tools/db_maintain.py --stats`） |

## 八、失败兜底话术

| 如果 | 就说 |
|---|---|
| 模型很慢（>10 秒） | "它在做一次真实取数：营业时间、票价、通行时长都要查。断网状态下会更快。" |
| 模型/网络挂了 | 直接切「强制离线」，同一句话演示完整链路 |
| 某个地名没认出来 | 顺势讲"我们宁可标待补地点，也不臆造一个像的地点"（这是设计选择） |
| 页面状态乱了 | 点左栏「重新开始」清会话，再演示；**不要现场手改数据库** |
