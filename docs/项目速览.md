# 项目速览（简历/面试用）

> 这份文件是给"快速了解这个项目"的人看的：一屏看懂做了什么、凭什么说做得好、哪些地方没做。
> 详细设计见 `code/docs/` 与源码注释。

---

## 一句话

用一句自然语言（「周六下午想去总统府和 1912，晚上 9 点前回学校」）生成一份**可执行**的当天行程：
自动判断说了几件事、每件事在哪儿、待多久、营业时间够不够、两点之间怎么走，排完存进本地数据库并以时间轴/日历/地图呈现。

## 核心设计取舍（面试重点）

**LLM 只负责「理解」和「给候选」；校验、取数、约束求解、解释全部在代码里。**

理由：口语输入里有大量不确定——地名可能认错、时长可能只给"看情况"、营业时间可能缺失、通行时长依赖实时路况。
把这些交给模型"一次性生成"，错在哪都无从解释。所以本项目的分工是：

| 谁 | 做什么 |
|---|---|
| LLM（DeepSeek） | 槽位候选、意图候选、话术组织（**不**做事实判断） |
| 代码 | 名称相似度校验、跨城拒绝、营业时间择时、通行时长推进、每日配额、冲突与备选、解释文案 |

配套的是**数据纪律**：取不到就留缺口——地名核不上转「待补地点」，门票没收录写「待核实」，天气超出 4 天窗口就说"无预报"，绝不编一个看起来合理的数。

## 架构（分层 + 端口适配器）

```
web（原生 SPA，无框架）
  │
web_api / lan_server（HTTP 接口层）
  │
services（编排：preview / commit / replan / drop / export …）
  │
├── domain
│   ├── intent.py      意图层：6 类意图 + 7 类动作切片
│   ├── engine.py      排程引擎：锁定优先 + 空档扫描 + 营业时间择时 + 通行推进
│   ├── ordering.py    顺序编排：闭馆早的先排 / 夜游类挪最后 / 同类就近串联
│   ├── hours.py       营业时间与闭馆日
│   ├── evidence.py    时长证据：官方 > OTA > 估算（三级）
│   └── consult.py     多轮顾问：槽位吸收 + 一次一问 + 草案生成
│
├── adapters
│   ├── amap.py        高德：POI / 路径 / 天气 / 静态图（Session 连接复用）
│   ├── deepseek.py    OpenAI 兼容接口，JSON 模式，温度 0
│   └── mock.py        离线实现（断网可用）
│
└── storage.py         SQLite + WAL + 缓存裁剪/VACUUM 维护
```

## 可以直接写进简历的四条

1. **从口语到可执行行程的完整闭环**：自然语言 → 意图识别（6 类意图 / 7 类动作切片）→ 约束排程（营业时间择时、真实通行推进时间轴、每日点位配额）→ 本地 SQLite 持久化 → 时间轴 / 日历 / 地图 / 精简导出。
2. **真实数据链路与降级设计**：接入 DeepSeek + 高德；时长证据分三级（官方 > OTA > 估算），POI 检索失败回退城市包、路径查询失败回退离线距离估算，**接口配额打满时自动降级不阻塞**，并在界面上标注数据来源。
3. **可回归的质量体系**：**1142 条**自动化用例（正式 1053 = 离线 1044 + 联网 9，扩展 89），离线回归 **844 passed / 0 failed**；**130 条**缺陷逐条记录现象 / 根因 / 修法 / 回归用例；自研 `tools/audit_code.py`（编译 + 装配冒烟 + AST 查重复定义、死代码、游离槽位）。
4. **用 profile 定位性能问题**：切日期一次 6 s，cProfile 显示 5 个高德请求各要 1 s、其中 **TLS 握手占 4 s**；改模块级 `requests.Session` 复用连接后降到 1 s 级。

## 关键数字（可自行复跑核对）

| 项 | 值 |
|---|---|
| 代码规模 | `nanjingtrip` 包 30+ 模块，前端原生 JS 约 2 300 行 |
| 自动化用例 | 1142（离线 1044 + 联网 9 + 扩展 89） |
| 离线回归 | 844 passed / 98 xfailed（按契约记录待修）/ 101 xpassed（已修好待撤标记）/ 0 failed |
| 缺陷台账 | D-01 ～ D-130 |
| 城市数据包 | 906 个点位（POI / 地铁站 / 沿线 2 km 配套） |
| 关键词数量 | 意图 6 类、动作切片 7 类、能力卡 8 张 |

> `xfail` 的用法：先把"应该怎样"写成契约用例并标 `xfail`，修好后自动变成 `xpassed`。
> 这比"把现状写成断言"更能说明还剩多少问题、修了多少。

## 诚实说明（面试被问到时照实说）

- **单人、本地运行、无部署、无真实用户量**，不是分布式系统，没有高并发场景。
- 意图识别**不是 100% 准**：短句、动词地名齐全的说法现在很准；长口语里带隐含上下文、中文数字、相对时间的，实测六类 300 条里约 75% 通过，剩余部分走"追问"或"退化成可编辑预览卡"，**不让猜错的结果直接进日程**。
- 城市包里的门票价格覆盖不全（906 个点位中只有餐饮/住宿带价），所以费用估算里门票多数是"待核实"——这是数据纪律的选择，不是没做完。
- 真实高德接口有 QPS 配额，联调期集中压测会打满，此时靠降级路径保证"慢但不挂"。
